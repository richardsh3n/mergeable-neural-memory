# Next research decision

**Use a learnability gate before funding a larger capacity sweep.** Under the
short follow-up budget, the neural reader mostly abstained even when given a
state encoded from all evidence. The packed baseline establishes that the
tasks have useful answers at the same byte budgets. It also sets a concrete
standard the learned model would have to beat or extend.

| Order | Proposed test | Decision it enables |
|---|---|---|
| 1 | Run a preregistered feasibility check on the original six-entity problem and one new capacity anchor. Cross the original 12-slot topology and the two-slot topology as diagnostic conditions. Keep the two-hop world-macro endpoint, a shared held-out corpus, prespecified fresh seeds and stopping rules. Report first-hop accuracy, known-answer recall and raw-union replay accuracy per fit. | Use the previous 90% replay gate on the easy anchor to decide whether these fits can diagnose a merger at all. Predeclare the new anchor's target, maximum compute and seed handling before running. |
| 2 | On a backbone that clears feasibility, compare the native reader with frozen-state linear and small nonlinear readouts and with an identical budget for the control probes. Compare local, full-union, and future-union writer objectives at matched example counts, keeping inherited and from-scratch models separate. Repeat the exact collision challenge at different evidence densities. | Distinguish destroyed distinctions, weak readout and ordinary adaptation forgetting. A real mechanism gain should survive a competent reader and seeds that vary independently of the test corpus. |
| 3 | Freeze a capacity design with relation density and hop count as separate factors. Vary bytes by more than one mechanism, with explicit parameter/compute disclosures. Include the packed table, a stronger byte-budgeted sparse reference, dedicated MAXSET and SUM, and the replay check. Analyze paired held-out worlds with any interval's fit scope stated. | Determine where learned retention degrades as workload grows. Treat cells where the table is exact as calibration and use the below-table regime for compression comparisons. |
| 4 | Set operational merge targets before changing the architecture. Define allowed drift, conflict semantics, source identity and what a later write does. For one query that genuinely requires A, B and C, add a third hop or a different reasoning primitive only after a design review. | Decide whether the project needs exact duplicate delivery semantics or can trade them for other retrieval benefits. Test update monotonicity and true three-source dependency before pretrained language-model integration. |

The first approval should specify the feasibility budget and the easy/new
anchors. The capacity matrix, three-hop changes, new writer/reader
architectures, and a language-model run remain proposed. The follow-up has no
evidence of a general neural compression advantage or of a replacement for a
structured table in this setting.

Method references include the standard distinction between mergeable
summaries and error guarantees, probe selectivity controls, and the additional
requirements behind state-based convergence. [Agarwal et al.](https://doi.org/10.1145/2500128) ·
